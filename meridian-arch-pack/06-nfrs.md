# 06-nfrs

| # | NFR | Family | Container(s) | Target | Test approach | Meridian justification | Anti-pattern to avoid |
|---|---|---|---|---|---|---|---|
| 1 | Cart-to-checkout p95 latency (EU) | Latency | Apollo GraphQL Gateway, Cart Service, Checkout Service | **p95 < 1500 ms** for EU checkout, including PSD2 SCA path | Nightly synthetic checkout from each EU region; fail build trend check if rolling p95 breaches target | Meridian must support **PSD2 SCA** on EU card payments, which makes sub-100ms checkout unrealistic; the target must include real auth round-trips | Treating SCA as an external exception and budgeting only app latency, which hides the real user-path cost |
| 2 | Identity verification latency | Latency | Identity Service, Auth0 | **p95 < 250 ms** for token validation + session refresh | Synthetic auth probe every 60 seconds per region; CI contract test on token/session flow | Meridian Phase 1 includes **unified identity** across web/mobile/store-assisted journeys; identity cannot become the new bottleneck | Adding extra synchronous profile lookups on every auth path instead of keeping auth verification lean |
| 3 | Black Friday checkout throughput | Reliability | Apollo GraphQL Gateway, Cart Service, Checkout Service, Order Database | **8000 RPS sustained** and **12000 RPS burst for 10 minutes** without error-rate breach | Load test on release candidate branch with peak profile replay; fail release if target is missed | Meridian explicitly treats **EU Black Friday outage** as a serious pain point; peak handling is a Phase 1 architecture concern | Putting SAP ECC on the hot path for normal checkout/cart operations, which collapses under burst load |
| 4 | Platform availability per region | Reliability | Apollo GraphQL Gateway, Checkout Service, Identity Service | **99.95% monthly availability per region** excluding planned maintenance | SLO monitor + synthetic probes; alert at **99.92%**, block release if resilience tests fail | The brief implies **stores must keep selling** and downtime is treated as an incident, but five-nines would exceed a realistic Phase 1 budget | Using a single shared failure domain across all regions or payment paths without isolation / graceful degradation |
| 5 | Phantom-stock cancellation rate | Quality | Inventory Read Cache (Redis), Order Event Bus (Kafka), Apollo GraphQL Gateway | **< 2%** of click-and-collect orders cancelled at pickup due to phantom stock | Daily reconciliation of cache/view vs SAP ECC plus tracked cancellation metric; fail drift alert if rate trends above threshold | Meridian’s current pain is about **~7% click-and-collect cancellation at pickup** due to phantom stock; Phase 1 must improve this materially | Lazy cache warm-up on first request, which guarantees stale or missing availability during peak traffic |
| 6 | Cost per completed checkout (platform share) | Cost | Apollo GraphQL Gateway, Identity Service, Cart Service, Checkout Service, Inventory Cache, Order Database | **< $0.04 per completed checkout** excluding payment-processor fees | Daily cost-allocation report from infrastructure billing mapped to containers; monthly budget guardrail review | The program has a **$42M / 18-month** envelope; Meridian needs unit economics, not only total program spend | Shipping features without container-level cost attribution, so cost growth is visible only after budget overruns |
| 7 | EU payment compliance and PII boundary | Security & compliance | Checkout Service, Stripe integration boundary, Order Database, Apollo GraphQL Gateway | **100%** of EU card payments must complete PSD2 SCA when required; **0 PII fields** may cross outside the PCI trust boundary in CI checks | CI control-conformance test + nightly data-boundary scan + payment-flow compliance test | Meridian explicitly carries **PSD2 SCA** and **PCI-DSS Level 1** obligations; prose compliance is not enough | Letting debug logs, events, or analytics payloads leak cardholder or protected identity data beyond the defined trust boundary |

## Notes
1. These budgets cover all five required families: **latency, cost, quality, reliability, security & compliance**.
2. Every row is tied to named containers from the Meridian Phase 1 container set.
3. Each budget includes an enforcement mechanism, not just production monitoring.
4. The hardest budget for the architecture to hold is likely **NFR #5** because cache freshness and SAP source-of-truth lag directly affect customer trust.
