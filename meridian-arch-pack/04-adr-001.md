# ADR-001: Adopt an event-driven inventory read model hydrated from SAP ECC

## Context
Meridian Phase 1 must bridge online and in-store inventory while SAP ECC remains the source of truth, and the program explicitly forbids a Big Bang cutover. The architecture also has to support omnichannel flows under an 18-month, $42M program with PSD2 SCA latency pressure and a junior internal product team.

## Decision
We will use an event-driven inventory read model hydrated from SAP ECC, with digital channels reading from the derived inventory view rather than calling SAP ECC synchronously for every user-facing inventory check.

## Why this option won
Compared with direct synchronous SAP reads, the event-driven read model gives Meridian better user-path latency and reduces runtime dependency on SAP behavior. Compared with buying a cross-channel inventory service, it keeps more architectural control inside Meridian and avoids pushing a load-bearing Phase 1 dependency into a vendor integration path.

## Alternatives Considered
1. **Direct synchronous reads against SAP ECC** — rejected because SAP batch-update reality and runtime latency would put user-facing availability and checkout flows directly on top of a legacy enterprise dependency that Meridian is trying to decouple from.
2. **Buy a cross-channel inventory service** — rejected because it improves speed to capability, but adds vendor dependency and procurement/integration risk inside a stage-gated program that already has major transformation complexity.

## Consequences
- **Positive:** Enables faster digital inventory reads, reduces direct runtime coupling to SAP ECC, and creates a stronger base for future omnichannel inventory features.
- **Negative:** Adds Kafka/eventing complexity, read-model correctness risk, and higher operational burden for a junior internal team.

## Agent-Readable Summary
All customer-facing inventory and cart-availability reads must come from the derived inventory read model, not direct synchronous SAP ECC calls. Do not place SAP ECC on the default runtime path for product-page, cart, or checkout availability checks; SAP may only be used as a bounded fallback path.
